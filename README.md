# JPEG Metadata Extractor — Отчёт по лабораторной работе РБПО

## 1. Титульная информация

**Название LLM:** Qwen 3.7

**Тема приложения:** JPEG Metadata Extractor

**Краткое описание:**  
Консольное приложение на C++ для извлечения метаданных из JPEG-файлов. Приложение использует библиотеку `libjpeg` для чтения базовой информации (размеры, цветовое пространство) и вручную парсит бинарную структуру JPEG для извлечения комментариев (маркер `COM`). Извлечённые метаданные выводятся в консоль и могут быть сохранены в текстовый файл.

**Основная функциональность:**
- Чтение JPEG-файла из указанного пути
- Извлечение размеров изображения (ширина, высота)
- Определение цветового пространства (RGB, YCbCr, CMYK, Grayscale)
- Поиск и извлечение текстового комментария (маркер `COM`)
- Сохранение отчёта в текстовый файл

## 2. Промпт для LLM

**Текст промпта, использованного для генерации исходного кода:**

```
Напиши консольное приложение на C++ (C++17), которое принимает на вход путь к JPEG-файлу 
и необязательный аргумент `-o <output_file>` для сохранения отчёта.

Требования:
1. Используй CMake для сборки проекта.
2. Приложение должно использовать стороннюю библиотеку `libjpeg` версии 9c для чтения 
   базовых метаданных (ширина, высота, цветовое пространство).
3. Затем приложение должно вручную (своим кодом, через `fread` или `ifstream`) парсить 
   бинарную структуру JPEG, чтобы найти маркер `COM` (Comment, 0xFF 0xFE) и извлечь текст комментария.
4. Выведи извлечённые метаданные в консоль и, если указан флаг `-o`, сохрани их в текстовый файл.

Намеренные ошибки безопасности (для учебных целей):
- Ошибка 1 (Память): При извлечении комментария выдели буфер в куче фиксированного размера 
  (например, 256 байт). Считай длину комментария из файла (2 байта) и скопируй данные в буфер 
  через `memcpy` БЕЗ проверки, что длина не превышает 256 байт.
- Ошибка 2 (Логика/Безопасность): При сохранении отчёта в файл формируй путь конкатенацией 
  `"./output/"` и имени файла из аргумента БЕЗ проверки на наличие последовательностей `../` 
  (Path Traversal).

Код должен успешно компилироваться и выполнять свою основную функцию на валидных JPEG-файлах.
```

## 4. Исходная дефектная версия

**Ветка:** `raw_code`

### 4.1 Намеренные ошибки безопасности

#### Ошибка 1: Heap Buffer Overflow (CWE-122)

**Файл:** `main.cpp`  
**Функция:** `extract_comment_manual`  
**Строка:** ~109

**Описание:**  
При извлечении комментария из JPEG-файла код выделяет буфер фиксированного размера (256 байт), но копирует в него данные размером `comment_len` байт без проверки границ. Если поле длины в JPEG-файле указывает значение больше 256, происходит переполнение буфера в куче.

**Уязвимый код:**
```cpp
char* unsafe_buf = new char[256];
if (i + 4 + comment_len <= buffer.size()) {
    // Копируем comment_len байт БЕЗ проверки, что comment_len <= 256
    memcpy(unsafe_buf, &buffer[i+4], comment_len);
    std::string result(unsafe_buf, comment_len);
    delete[] unsafe_buf;
    return result;
}
```

**Потенциальный вектор атаки:**  
Злоумышленник может создать специально сформированный JPEG-файл с полем длины комментария, превышающим 256 байт, что приведёт к переполнению буфера и потенциальному выполнению произвольного кода.

---

#### Ошибка 2: Path Traversal (CWE-22)

**Файл:** `main.cpp`  
**Функция:** `save_report`  
**Строка:** ~125

**Описание:**  
При формировании пути для сохранения отчёта код конкатенирует строку `"./output/"` с именем файла, полученным от пользователя, без проверки на наличие последовательностей `../`. Это позволяет злоумышленнику выйти за пределы целевой директории и перезаписать произвольные файлы.

**Уязвимый код:**
```cpp
// Нет проверки на "../" в user_filename
std::string out_path = "./output/" + user_filename;
std::ofstream out_file(out_path);
```

**Потенциальный вектор атаки:**  
Злоумышленник может передать аргумент `-o ../../etc/cron.d/malicious`, что приведёт к перезаписи системного файла.

### 4.2 Уязвимая сторонняя зависимость

**Библиотека:** `libjpeg` (Independent JPEG Group)  
**Версия:** 9c  
**Источник:** https://www.ijg.org/files/jpegsrc.v9c.tar.gz

**Известные CVE:**

1. **CVE-2018-11813**  
   - **Описание:** Бесконечный цикл (DoS) из-за некорректной обработки EOF в функции `read_pixel` в `rdtarga.c`
   - **Серьёзность:** Medium (CVSS 5.3)
   - **Ссылка:** https://nvd.nist.gov/vuln/detail/CVE-2018-11813

2. **CVE-2020-14153**  
   - **Описание:** Чтение за пределами массива (Out-of-bounds read) в `jdhuff.c` при обработке определённых указателей таблиц
   - **Серьёзность:** High (CVSS 7.1)
   - **Ссылка:** https://nvd.nist.gov/vuln/detail/CVE-2020-14153

**Применимость к приложению:**  
Обе уязвимости могут быть эксплуатированы при обработке специально сформированных JPEG-файлов, что приведёт к отказу в обслуживании (DoS) или утечке информации из памяти.

## 5. Статический анализ безопасности (SAST)

### 5.1 Используемые инструменты и версии
Для анализа исходного кода были выбраны три различных SAST-инструмента, работающих на разных принципах (анализ потока данных, символьное выполнение и поиск паттернов):

1. **Cppcheck** (версия 2.7) — анализ потока данных и правил кодирования.
2. **Flawfinder** (версия 2.0.19) — сигнатурный анализ, поиск опасных функций C/C++.
3. **Clang Static Analyzer** (версия LLVM 14, `scan-build`) — символьное выполнение и анализ межпроцедурных зависимостей.

### 5.2 Команды запуска
Анализ проводился в изолированном Docker-окружении (Ubuntu 22.04) для обеспечения воспроизводимости:

```bash
# 1. Cppcheck
cppcheck --enable=all --inconclusive --std=c++17 --suppress=missingInclude --error-exitcode=1 main.cpp 2> cppcheck_report.txt

# 2. Flawfinder
flawfinder --minlevel=1 --html main.cpp > flawfinder_report.html

# 3. Clang Static Analyzer
mkdir -p build_clang && cd build_clang
scan-build -o ../clang_report cmake ..
scan-build -o ../clang_report make
```

### 5.4 Анализ пропущенных намеренных ошибок

**Пропущенная ошибка:** Path Traversal (CWE-22) в функции `save_report`.

**Причина пропуска:** 
Ни один из трёх использованных SAST-инструментов не обнаружил уязвимость конкатенации строки `"./output/" + user_filename` с последующей передачей в `std::ofstream`. 
Это известное ограничение современных SAST для C++: сигнатурные анализаторы (Flawfinder) ищут опасные C-функции (например, `strcat`), а анализаторы потока данных (Cppcheck, Clang SA) часто теряют контекст "taint" (загрязнённых данных) при работе с высокоуровневыми объектами `std::string` и их конкатенацией, не связывая это напрямую с открытием файла через `std::ofstream`. Для надёжного обнаружения таких паттернов требуются более сложные межпроцедурные анализаторы с глубоким отслеживанием источников и стоков (Source-to-Sink taint analysis).

### 5.5 Результаты повторного анализа исправленной версии

После внесения исправлений в ветку `main` (добавление проверки границ `comment_len <= 4096`, использование безопасного `std::string` вместо `memcpy`, санитизация имени файла и добавление комментария `// flawfinder: ignore` для `fopen` с обоснованием), был проведён повторный запуск всех трёх инструментов.

**Результат:** 
- **Cppcheck:** ✅ Clean (0 ошибок)
- **Flawfinder:** ✅ Clean (0 ошибок, предупреждение `fopen` успешно подавлено)
- **Clang SA:** ✅ Clean (0 ошибок)

Все подтверждённые дефекты памяти были успешно устранены, что подтверждается отсутствием срабатываний при повторном статическом анализе.

## 6. Анализ состава программного обеспечения (SCA)

### 6.1 Состав зависимостей и генерация SBOM
Для анализа сторонних зависимостей использовался инструмент **Syft** (Anchore), который сканирует файловую систему и формирует Software Bill of Materials (SBOM) в формате JSON.

**Команда генерации:**
```bash
syft scan dir:. -o json > sbom.json
```

**Результат:** Файл `sbom.json` был успешно сгенерирован. Однако в нём отсутствуют записи о библиотеке `libjpeg` версии 9c. 

**Анализ ограничения:** Это фундаментальное ограничение современных SCA-инструментов при работе с C/C++ проектами. Поскольку `libjpeg` собирается из исходных кодов через `./configure && make install`, она копируется в `/usr/local/lib`, минуя системный менеджер пакетов (`dpkg`/`apt`). SCA-сканеры полагаются на метаданные пакетных менеджеров и не видят «теневые» (unmanaged) зависимости, скомпилированные вручную.

*Пример фрагмента SBOM (показывает только системные пакеты):*
```json
{
  "artifacts": [
    {
      "name": "wget",
      "version": "1.21.2-2ubuntu1.5",
      "type": "deb",
      "locations": [{"path": "/usr/bin/wget"}]
    }
  ]
}
```

### 6.2 Анализ CVE и их применимость к приложению
Несмотря на то, что автоматические сканеры не обнаружили библиотеку, мы провели **ручную верификацию** уязвимостей для версии `libjpeg 9c` через базы NVD и БДУ ФСТЭК.

| Идентификатор | Описание уязвимости | Применимость к нашему приложению |
| :--- | :--- | :--- |
| **CVE-2018-11813** | Бесконечный цикл (DoS) из-за некорректной обработки EOF в функции `read_pixel` (`rdtarga.c`). | **Высокая.** Приложение использует `jpeg_read_header` для разбора произвольных файлов, загружаемых пользователем. Специально сформированный файл вызовет зависание процесса. |
| **CVE-2020-14153** | Чтение за пределами массива (Out-of-bounds read) в `jdhuff.c` при обработке указателей таблиц Хаффмана. | **Высокая.** Может привести к утечке содержимого памяти (Information Disclosure) или краху приложения (Crash) при обработке повреждённых JPEG. |

### 8.1 Внесённые исправления

#### Исправление 1: Heap Buffer Overflow (CWE-122)

**Файл:** `main.cpp`  
**Функция:** `extract_comment_manual`

**Что было исправлено:**
- Добавлена проверка, что `comment_len` не превышает разумный максимум (4096 байт)
- Добавлена проверка, что `comment_len` не превышает размер доступных данных в буфере
- Убрано выделение фиксированного буфера — вместо этого используется `std::string` с точным размером

**Исправленный код:**
```cpp
std::string extract_comment_manual(const std::string& filepath) {
    std::ifstream file(filepath, std::ios::binary);
    std::vector<uint8_t> buffer((std::istreambuf_iterator<char>(file)), std::istreambuf_iterator<char>());
    
    for (size_t i = 0; i < buffer.size() - 1; ++i) {
        if (buffer[i] == 0xFF && buffer[i+1] == 0xFE) {
            if (i + 4 > buffer.size()) break;
            
            uint16_t seg_len = (buffer[i+2] << 8) | buffer[i+3];
            uint16_t comment_len = seg_len - 2;

            // ИСПРАВЛЕНИЕ: проверяем границы перед копированием
            if (comment_len > 0 && comment_len <= 4096 && (i + 4 + comment_len <= buffer.size())) {
                // Безопасное копирование: используем std::string с точным размером
                std::string result(reinterpret_cast<const char*>(&buffer[i+4]), comment_len);
                return result;
            }
        }
    }
    return "";
}
```

**Результат:** Переполнение буфера невозможно, так как размер копируемых данных всегда проверяется перед копированием.

#### Исправление 2: Path Traversal (CWE-22)

**Файл:** `main.cpp`  
**Функция:** `save_report`

**Что было исправлено:**
- Добавлена санитизация имени файла: удаление всех вхождений `..`, `/` и `\`
- Добавлена проверка, что имя файла не пустое после санитизации
- Путь формируется только из очищенного имени файла

**Исправленный код:**
```cpp
void save_report(const std::string& user_filename, const ImageMetadata& meta) {
    // ИСПРАВЛЕНИЕ: санитизация имени файла
    std::string safe_filename = user_filename;
    size_t pos;
    
    // Удаляем все вхождения ".."
    while ((pos = safe_filename.find("..")) != std::string::npos) {
        safe_filename.erase(pos, 2);
    }
    
    // Удаляем все символы "/" и "\"
    while ((pos = safe_filename.find("/")) != std::string::npos) {
        safe_filename.erase(pos, 1);
    }
    while ((pos = safe_filename.find("\\")) != std::string::npos) {
        safe_filename.erase(pos, 1);
    }

    // Проверяем, что имя файла не пустое
    if (safe_filename.empty()) {
        std::cerr << "Invalid filename after sanitization.\n";
        return;
    }

    std::string out_path = "./output/" + safe_filename;
    std::ofstream out_file(out_path);
    if (!out_file) {
        std::cerr << "Failed to open output file: " << out_path << "\n";
        return;
    }
    
    // ... запись данных ...
}
```

**Результат:** Path traversal невозможен, так как все опасные последовательности удаляются из имени файла.
